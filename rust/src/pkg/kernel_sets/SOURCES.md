The wire format uses Linux's public UAPI: [Netlink framing and attributes](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/netlink.h), [netfilter subsystem and transaction headers](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/netfilter/nfnetlink.h), [nftables messages and set attributes](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/netfilter/nf_tables.h), and [ipset protocol attributes](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/netfilter/ipset/ip_set.h).

The [kernel's nftables element implementation](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_tables_api.c) rejects timeout attributes on interval end markers. This module attaches explicit timeouts only to the interval start.

Compatibility was checked against the [external Go baseline](https://github.com/xfy-see/mosdns): `pkg/nftset_utils/handler.go`, `plugin/executable/nftset/nftset_linux.go`, `plugin/executable/ipset/ipset_linux.go`, and its pinned dependencies. Default element timeouts are omitted, matching the existing plugins. Explicit DNS TTL mode is separate and opt-in.

The high-level handlers only add elements to existing sets. They never create tables, sets, rules, or hooks. Wire unit tests do not mutate kernel state. `rust/tests/linux_runtime.rs` provides four ignored privileged tests that use the same native netlink transport to create uniquely named `mosdns_rs_test_*` fixtures, read back their elements, and remove them through explicit cleanup plus a Drop fallback. The nftables fixtures contain no chains, rules, or hooks. They cover IPv4, IPv6, CIDR intervals, duplicate ipset prefixes, and default/explicit timeouts. A fifth ignored test queries IPSET_CMD_PROTOCOL without creating any objects, so an unavailable subsystem is reported as an error rather than skipped.

The ignored tests compile for Linux. Historical isolated nftables tests passed on the migration test device; IPSet fixtures and a protocol-only query failed with EINVAL, and no supporting IPSet kernel module was found. IPSet element interoperability remains unverified. Those logs, capability probes, and source/binary bindings remain under `deployments/20261007-131-mosdns-rust/` in the original Go checkout; private deployment evidence is not copied to this repository. Historical results do not establish coverage of a new commit.

Linux's [nfnetlink dispatch](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nfnetlink.c#L216) returns EINVAL when a subsystem is unavailable. The historical Go capability probe returned DNS NOERROR, but the pinned Go IPSet library sends a message without consuming its kernel ACK; that result cannot establish IPSet support. Ordinary unit passes are separate from privileged kernel readback.

Build the harness on GitHub and verify the downloaded Linux artifact using the [repository workflow](../../../../docs/github-workflow.md). On an isolated host with root/CAP_NET_ADMIN, explicitly opt into individual ignored test names from the harness list. The ipset element tests additionally require the kernel's `hash:net` type. Tests use exclusive creation and only clean up objects they created. An external kill or an unknown-outcome netlink timeout can bypass cleanup; unique fixture names identify any remaining object without touching production sets. Record readback and cleanup for each test; do not count unexecuted ignored tests as passes.

Native sockets use OwnedFd, including error paths, and handler close drops the socket and cached metadata. Each native exchange has a monotonic deadline, accepts replies only from the kernel, and matches known sequences; stale ACKs cannot finish a current operation. Datagrams are limited to 64 KiB. Metadata requests keep one result; the low-level multipart dump API retains the full dump in memory and is intended for isolated fixture administration, not the query path.

The async wrappers run synchronous operations with spawn_blocking. Cancelling the awaiting future does not cancel an already started blocking operation, and waiting for the handler mutex is outside the per-exchange timeout. IPSet batches add one acknowledged RR at a time, so a whole batch may take longer than one exchange timeout and can be partially applied before a later error. There is no independent kernel-set queue limit or whole-batch deadline.

Explicit timeout encoding rounds upward to milliseconds for nftables and seconds for IPSet. However, Linux [IPSet timeout normalization](https://github.com/torvalds/linux/blob/v6.12/include/linux/netfilter/ipset/ip_set.h#L430) clamps values above 2,147,483 seconds. The current encoder checks the wire's u32 limit but not that smaller kernel limit. Consequently, the opt-in DNS TTL policy cannot guarantee its requested minimum for extremely long IPSet TTLs; rejecting these values and testing readback on a supporting kernel remain follow-up work. The production quick syntax keeps the existing set-default timeout policy.
